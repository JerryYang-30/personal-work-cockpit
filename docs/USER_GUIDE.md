# 个人工作驾驶舱 V1.0｜使用手册

## 1. 先理解它的用途

个人工作驾驶舱不是“把所有工作信息都塞进 Excel”，而是保存**足以让你放心忘掉、又能随时恢复的当前工作状态**。

日常只需要回答几个问题：

1. 这件事是什么？
2. 现在处于什么状态？
3. 下一步轮到谁？
4. 我回来以后第一步做什么？
5. 什么时候它应该重新进入我的注意力？
6. 有没有真正的截止时间？

## 2. 一行代表什么

**一行 = 一个需要持续关注到闭环的事项。**

不要把每个动作都拆成一行。例如“平台组件申请”可以是一条事项，完整流程写：

`☑填申请表 → ☑确认模板 → ☐签章 → ☐提交工单 → ☐结单`

日常只维护“下一步动作”。

## 3. 最低成本录入

新事项出现时，不要求一次填满。最低建议填写：

`项目 + 事项 + 状态 + 当前球权 + 下一步动作`

有价值时再补：事项类型、定位入口、时间、完整流程、加速因素等。

## 4. 状态怎么选

| 状态 | 含义 | 你还需要主动关注吗 |
| --- | --- | --- |
| 待处理 | 球在自己，还没开始 | 是 |
| 处理中 | 球在自己，已经开始 | 是 |
| 等待他人 | 当前球在别人手里，但事项仍由你负责收口 | 到下一关注时间再看 |
| 受阻 | 因条件/问题无法继续 | 是 |
| 已完成 | 已闭环 | 否 |
| 已移交 | 已正式交给其他同事继续负责 | 否 |
| 已取消 | 不再继续 | 否 |

**等待他人 ≠ 已移交。**

等待他人必须设置下一关注时间；已移交表示责任已正式转出，会自动进入“4 暂不关注”。

## 5. 关注级别怎么理解

系统自动生成：

- `1 立即处理`
- `2 今日处理`
- `3 近期关注`
- `4 暂不关注`

它不是“客观重要程度”，而是**现在应该给多少注意力**。

典型规则：

- 当前任务、已经到截止时点、止损/阻塞事项 → 立即处理；
- 下一关注已经到、今日/明日 deadline、强制今日 → 今日处理；
- 等待他人且下一关注还没到 → 暂不关注；
- 已完成 / 已取消 / 已移交 → 暂不关注；
- 其他未完成事项 → 近期关注。

如果机器判断不符合真实语境，用“人工置顶”纠偏，不要为了修算法而给所有事项增加评分。

## 6. 时间字段

时间字段固定相邻：

`添加时间 → 最近更新时间 → 下一关注时间 → 截止时间 → 滞留天数`

### 添加时间
第一次知道“有这么一件事”的时间。

### 最近更新时间
最近一次发生**实质进展**的静态时间。不要用 `TODAY()` / `NOW()` 代替。

### 下一关注时间
回答：**什么时候它必须重新进入我的注意力？**

- 仅日期 / 上午 → 08:30
- 下午 → 14:30
- 明确时点 → 直接输入，如 15:30

### 截止时间
回答：**最晚什么时候完成/提交，否则会产生现实后果？**

- 上午前 → 12:00
- 仅日期 / 当天前 → 17:30
- 明确时点 → 直接输入

### 滞留天数
自动按自然日计算“今天 - 最近更新时间”，用于识别长期没有实质进展的事项。

## 7. 被打断以后怎么快速回来

四个字段组合使用：

- `▶当前`：被打断前实际正在处理的唯一事项；
- `当前进展`：恢复上下文；
- `下一步动作`：回来后第一步做什么；
- `定位入口`：从哪里重新进入，如群聊关键词、工单号、系统菜单、文件路径。

`定位入口`只做“导航”，不要把它扩展成文件管理系统。

## 8. 日志怎么记

日志粒度是：**事项 × 有意义的事件**。

不需要记录每条聊天、每次编辑。通常一天一条即可；如果同一事项当天发生多个关键节点，可以多条。

所有项目共用一张日志，筛选“项目”就能得到项目时间线。

## 9. 推荐日常节奏

### 早上
看“立即处理 / 今日处理”，选一个 `▶当前`。

### 工作过程中
新事项轻量录入；实质变化才更新状态、进展、下一步和最近更新时间。

### 等待别人
填 `等待他人 + 当前球权 + 下一关注时间`，然后放心沉底。

### 下班前
检查待催缺日期、收口当天变化、按需写日志，然后关闭工作簿。

## 10. 不要为了“更专业”做这些事

- 给每件事填写重要度/紧急度/影响度 1~5；
- 为每个步骤创建一行；
- 把联系人、文件版本、项目背景全部塞进主表；
- 每发生一次聊天就写一条日志；
- 为了自动化让核心工作簿依赖宏、Python 或 AI。

如果一个新增字段不能显著减少遗漏、重复维护或恢复上下文的成本，它大概率不应该进入主表。
