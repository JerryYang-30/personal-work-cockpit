# 项目文件夹与版本管理建议

这套方法与驾驶舱有关联，但**不直接写入事项主表字段**。目标是让项目文件可找、当前版本明确、目录结构稳定。

## 原则

> **工作分类可以细，文件分类应该粗。**

推荐按需使用稳定的大类，而不是每种事项建一个一级目录：

```text
项目A/
├─ 00_项目总览
├─ 01_需求与设计
├─ 02_数据_资源_权限
├─ 03_建设_配置_测试
├─ 04_架构_安全_并网
├─ 05_验收_移交
├─ 06_会议_汇报
└─ 99_临时
```

哪个类别真正产生文件，再创建哪个；不必复制一堆空目录。

## 当前版 + 历史版

```text
03_概设/
├─ XX项目概设.docx
└─ _历史版本/
   ├─ XX项目概设_20260820.docx
   └─ XX项目概设_20260827_报审版.docx
```

规则：

- 最外层无日期/版本号的文件 = 当前工作版；
- 关键节点前才归档旧版；
- 历史文件名建议：`主题_YYYYMMDD_节点说明.ext`；
- 避免“最终版 / 最终版2 / 真最终”等命名。

`99_临时` 可以作为缓冲区，但应定期归档或删除。

未来可由 Python/OpenCode 根据项目 Checklist **创建目录骨架**，但不应在未确认时自动移动已有文件。
