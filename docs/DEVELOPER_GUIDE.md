# 个人工作驾驶舱 V1.0｜开发与 AI 接手指南

## 1. 文档优先级

修改模板前按以下顺序读取：

1. `spec/tracker_spec.json` — 当前版本机器可读事实源；
2. `docs/PRODUCT_PRINCIPLES.md` — 产品原则和边界；
3. 本文档 — 实现与回归约束；
4. `docs/USER_GUIDE.md` — 用户语义。

用户最新明确需求始终优先于仓库文档。

## 2. 技术边界

目标环境：

- 统信 UOS；
- WPS 企业版；
- 标准 `.xlsx`；
- 核心能力不依赖 VBA/宏；
- Python/OpenCode/AI 仅作为增强层；
- 敏感工作数据不得默认上传公网 AI。

## 3. 工作簿结构

### 工作事项台账

权威列顺序：

`A ▶当前 | B 关注级别 | C 项目 | D 事项类型 | E 事项 | F 状态 | G 当前球权 | H 当前进展 | I 下一步动作 | J 定位入口 | K 添加时间 | L 最近更新时间 | M 下一关注时间 | N 截止时间 | O 滞留天数 | P 完整流程 | Q 加速因素 | R 人工置顶`

时间字段 `K:O` 必须保持连续。

### 其他 Sheet

- `工作事项日志`：历史事件，不做主表镜像；
- `使用说明`：面向用户；
- `下拉列表`：枚举与时间配置。

## 4. 状态模型

固定状态：

`待处理 / 处理中 / 等待他人 / 受阻 / 已完成 / 已移交 / 已取消`

关键语义：

- `等待他人`：仍由用户负责收口，必须设置下一关注时间；
- `已移交`：责任正式转出，无条件为 `4 暂不关注`，旧截止不再触发逾期；
- 重新接手时由用户明确改回待处理/处理中，系统不要自动猜测。

## 5. 关注级别

四级标签必须保持纯文本：

`1 立即处理 / 2 今日处理 / 3 近期关注 / 4 暂不关注`

不要引入 emoji 作为必要语义，也不要改成不可解释的数值评分模型。

当前公式以 `spec/tracker_spec.json -> formulas.attention_level` 为权威。

规则顺序不能随意改变：

1. 已完成/已取消/已移交 → 暂不关注；
2. 当前任务、强制立即、截止已到、止损/阻塞 → 立即；
3. 强制今日、待催缺日期、下一关注已到、今日/明日 deadline 等 → 今日；
4. 等待他人且下一关注在未来 → 暂不关注；
5. 其他未完成 → 近期。

## 6. 时间模型

系统时钟必须使用 `NOW()`。

### 下一关注时间 M

- 仅日期 / 上午：08:30；
- 下午：14:30；
- 其他明确时间：真实时点。

### 截止时间 N

- 上午前：12:00；
- 仅日期 / 当天前：17:30；
- 其他明确时间：真实时点。

只填日期时底层可能是 00:00，公式不得直接把它解释为午夜到期，必须按以上字段语义兜底。

`最近更新时间` 是静态历史事实，严禁改成 `TODAY()` / `NOW()` 动态公式。

## 7. 数据验证

必须引用 `下拉列表` Sheet 作为统一枚举源：

- `A ▶当前`
- `D 事项类型`
- `F 状态`
- `R 人工置顶`

`Q 加速因素`提供单标签下拉建议，但必须允许手工组合，例如：`领导DDL｜阻塞`。

以下字段保持自由文本，不为“下拉化”而增加维护表：

- 项目；
- 当前球权；
- 定位入口。

定位入口应保留“选定单元格时显示输入信息”，提示聊天、系统、工单和文件路径示例。

## 8. 视觉约束（不可无意破坏）

### 主表

- 核心区 `A:O`：深蓝表头 `#2F5597` + 白色数据底；
- 辅助区 `P:R`：深灰表头 `#5B6573` + 浅灰数据底 `#EEF1F4`；
- 字体：Microsoft YaHei，正文 10pt；
- 数据区 `A5:R300`：必须同时存在 `#D9E1E8` 浅灰横向 + 纵向 thin 细边框；
- 不使用整行蓝色斑马纹替代基础网格；
- 项目列每行重复，不使用数据区合并单元格。

### 第一行 KPI

信息卡片之间必须用无填充、无边框的空白格形成间隔。

固定间隔：`C1 / F1 / I1 / L1 / O1:R1`。

禁止整行铺色或复制列格式污染这些间隔格。

### 子表

以下内容区同样必须保留浅灰横纵细网格：

- 日志：`A2:I300`
- 使用说明：`A3:B36`
- 下拉列表：`A2:H17`

基础网格不得覆盖已有表头、章节底色、数据验证或条件格式。

## 9. 条件格式必须保留

至少包括：

- 关注级别颜色；
- 等待他人/受阻/完成/取消/已移交状态样式；
- 等待他人缺下一关注时间告警；
- 截止逾期告警（必须排除已完成/已取消/已移交）；
- 下一关注 08:30/14:30 的“上午/下午”显示；
- 截止 12:00/17:30 的“上午前/日前”显示；
- `▶当前` 数量 > 1 的顶部告警。

移动列以后必须重新检查所有条件格式公式引用。

## 10. 修改原则

新增功能前必须回答：

1. 它解决什么真实痛点？
2. 不做会造成什么实际损失？
3. 是否增加每天/每次都要维护的新动作？
4. 能否由现有字段推导？
5. 能否先做更小的可选增强？

默认不要：

- 增加 1~5 主观评分字段；
- 合并下一关注和截止；
- 合并添加时间和最近更新时间；
- 把当前球权改成总责任人；
- 把日志做成主表每次编辑的镜像；
- 让 Python/AI 成为核心功能前提；
- 恢复数据区合并单元格。

## 11. 推荐增强方式

未来脚本应独立于工作簿核心，例如：

- 快照差异 → 日志候选 → 用户确认 → 追加；
- 项目事项类型统计 → Checklist 建议；
- 按 Checklist 创建文件夹骨架；
- 使用内网模型对日志生成周报/复盘。

任何自动写入都应：先备份、可预览、可取消，避免静默破坏主表。

## 12. 回归检查清单

每次修改 `.xlsx` 后至少验证：

- [ ] WPS 企业版可打开、编辑、另存；
- [ ] 无 `#REF! / #VALUE! / #NAME? / #DIV/0!`；
- [ ] 状态、事项类型、人工置顶等下拉正常；
- [ ] 已移交始终为暂不关注；
- [ ] 等待他人缺下一关注时间会告警；
- [ ] 下一关注/截止日期的默认时点语义正确；
- [ ] 条件格式自然语言时段显示正常；
- [ ] 主表和子表横纵细网格完整；
- [ ] 第一行 KPI 留白未被污染；
- [ ] 移列后公式/条件格式引用没有错位；
- [ ] 新增功能没有无意义增加日常维护动作；
- [ ] `spec/tracker_spec.json` 与实际工作簿同步。

## 13. 版本策略

- `V1.0` 是首个正式发布版本；
- 此前内部迭代统一视为 `0.x` 内测阶段；
- 公开版本文档描述**当前产品事实**，不追加“某某版本补充需求”式流水账；
- 版本说明只记录用户真正需要知道的正式发布变化。
